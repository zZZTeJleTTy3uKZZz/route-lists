# route-lists

Два списка маршрутизации в формате `rule-set` sing-box (исходный вид, JSON).

| Файл | Что в нём |
|---|---|
| `via-proxy.json` | адресаты, к которым соединение устанавливается через прокси-выход |
| `direct.json` | адресаты, к которым соединение устанавливается напрямую, без прокси-выхода |

## Формат

Каждый файл — `rule-set` версии 3 в исходном виде. Поддерживаемые поля правил
описаны в документации sing-box: `domain`, `domain_suffix`, `domain_keyword`,
`domain_regex`, `ip_cidr`.

```json
{
  "version": 3,
  "rules": [
    { "domain_suffix": ["example.com"] }
  ]
}
```

## Применение

Клиент sing-box принимает эти файлы как удалённый `rule-set` и перечитывает их
по заданному сроку:

```json
{
  "type": "remote",
  "tag": "via-proxy",
  "format": "source",
  "url": "https://raw.githubusercontent.com/<owner>/route-lists/main/via-proxy.json",
  "update_interval": "6h"
}
```

## Правка

Правьте JSON и отправляйте изменение. Проверка формата идёт при сборке:
`python3 tools/validate.py`.

Файлы читаются программами, поэтому:

- одна запись — один адресат, без повторов;
- домены в нижнем регистре, без схемы и без завершающей точки;
- `ip_cidr` — с маской (`198.51.100.0/24`), в том числе для одиночного адреса (`/32`).
