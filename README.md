# route-lists

Два списка маршрутизации в формате `rule-set` sing-box (исходный вид, JSON).

| Файл | Что в нём |
|---|---|
| `via-proxy.json` | адресаты, к которым соединение устанавливается через прокси-выход |
| `direct.json` | адресаты, к которым соединение устанавливается напрямую, без прокси-выхода |

## Формат

Каждый файл — `rule-set` версии 3 в исходном виде. Поддерживаемые поля правил
описаны в документации sing-box: `domain`, `domain_suffix`, `domain_keyword`,
`domain_regex`, `ip_cidr`.

```json
{
  "version": 3,
  "rules": [
    { "domain_suffix": ["example.com"] }
  ]
}
```

## Применение

Клиент sing-box принимает эти файлы как удалённый `rule-set` и перечитывает их
по заданному сроку:

```json
{
  "type": "remote",
  "tag": "via-proxy",
  "format": "source",
  "url": "https://raw.githubusercontent.com/zZZTeJleTTy3uKZZz/route-lists/main/via-proxy.json",
  "update_interval": "6h"
}
```

## Как списки наполняются

`via-proxy.json` и `direct.json` — не рукописные файлы. Их собирает
`tools/build_lists.py` из четырёх внешних источников и наших собственных
добавок, поэтому набор обновляется сам.

### Источники

| Источник | Что берём | Куда | Лицензия |
|---|---|---|---|
| [lib4u/amnezia-tunneling-ru](https://github.com/lib4u/amnezia-tunneling-ru) — `amnezia-ip-lite.json` | подсети российских адресатов | `direct.json` | лицензия не указана |
| [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) — `Russia/outside-raw.lst` | домены, доступные только из России | `direct.json` | лицензия не указана |
| [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) — `Russia/inside-raw.lst` | домены, доступные только за пределами России | `via-proxy.json` | лицензия не указана |
| [1andrevich/Re-filter-lists](https://github.com/1andrevich/Re-filter-lists) — `domains_all.lst` | домены и отдельные адреса | `via-proxy.json` | MIT |

Распределение по двум спискам задано в `tools/sources.json`: чтобы адресат
попал в другой список, правьте там. Список источников, их вид и нижний предел
записей — тоже этот файл.

Лицензии перечислены по данным репозиториев-источников на 05.11.2026. У двух
источников файла лицензии нет — для них указано «лицензия не указана», а не
предположение.

### Свои добавки

`own/via-proxy.txt` и `own/direct.txt` — простые списки, которые ведём мы: одна
запись на строку, домен (`example.org`) или подсеть (`198.51.100.0/24`), строка
с `#` — пояснение.

Как склейка с ними поступает:

- свои записи стоят в начале списка, первыми правилами;
- источник их не перетирает: если запись есть и у нас, и в источнике, остаётся наша;
- своя запись главнее источников и в другом списке: адресат, названный в
  `own/via-proxy.txt`, не попадёт в `direct.json`, даже если источник положил его
  туда, и наоборот;
- одна и та же запись в обоих своих файлах — противоречие, склейка откажется.

Если адресат из источников попал сразу в оба списка, склейка пишет об этом
предупреждение: какой список главнее, решает порядок правил в клиенте. Перенести
адресат в нужный список можно своей записью — она перекроет источник.

### Обновление по расписанию

`.github/workflows/refresh.yml` собирает списки раз в сутки (03:17 UTC) и умеет
запускаться вручную (`Actions` → `refresh` → `Run workflow`).

Порядок в нём жёсткий: склейка → `tools/validate.py` → коммит. Не прошла
проверка — коммита нет, рабочие файлы остаются прежними.

Защита от обвала объёма: если источник отдал пусто, меньше своего нижнего
предела (`min_entries` в `tools/sources.json`) или меньше 10% от прошлого удачного
запуска, склейка отказывается целиком и не трогает рабочие списки. Прошлые
объёмы лежат в `state/sources.json` и обновляются только вместе со списками.

Если источник временно недоступен, его можно пропустить вручную и собрать списки
из остальных: `python3 tools/build_lists.py --skip <id>`. Прошлый объём
пропущенного источника в состоянии сохраняется.

## Правка

- Свои адресаты — в `own/via-proxy.txt` и `own/direct.txt`, они переживут
  следующую склейку.
- Источники и их распределение — в `tools/sources.json`.
- `via-proxy.json` и `direct.json` правкой руками не ведутся: следующий запуск их
  перезапишет.

Локальная проверка:

```sh
python3 -I tools/build_lists.py   # склейка
python3 -I tools/validate.py      # формат
python3 -I tools/selftest.py      # самопроверка склейки, сеть не нужна
```

`tools/selftest.py` проверяет на местных образцах то, чего не видно в готовом
файле: порядок своих добавок, перекрытие источников и отказы при пустом или
урезанном источнике.

Файлы читаются программами, поэтому:

- одна запись — один адресат, без повторов;
- домены в нижнем регистре, без схемы и без завершающей точки;
- `ip_cidr` — с маской (`198.51.100.0/24`), в том числе для одиночного адреса (`/32`).
